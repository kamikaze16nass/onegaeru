## 設定と検証

`public.pyon_config.rules` が難易度の設定元。004に初期値を記載。適用後の調整はこの行を管理者から更新する（既存migrationは書き換えない）。各プレイは開始時の設定を保存するため、進行中に設定変更が混ざらない。

- `levels`: 次のジャンプ番号の上限、判断時間（ms）、片方が危険になる確率。次の1〜10回は2500ms、11〜20回は2200ms…101回以降1000ms。
- `kpChance`: 安全な候補ごとに5%。危険な候補には配置しない。
- `jumpMs`: 240ms。見た目のジャンプCSSも240ms。
- `networkGraceMs`: DB判定にのみ3000msの通信猶予。画面の判断時間は規定値のまま。応答を受けて着地を表示した時に画面のタイマーを開始する。極端に遅い回線ではDBが時間切れと判定しうる。1ジャンプにつきRPCが1往復するため実機でテンポを確認する。
- 報酬: `min(10, ceil(score / 10) * 2)`（0点は0）+拾得KP、1回10・日本時間の1日30まで。

`npm run test:pyon` はPGlite上で既存schemaと追加migrationを実行し、生成・境界・再送・RLSを検証する。Supabaseのauthとpgcryptoはテスト用fixture。実DBのネットワーク／複数接続の同時実行テストの代替ではない。

`npm run test:pyon:browser` はMicrosoft Edgeを使い、375/390/430/1024pxで実コンポーネントをRPCモックに接続して検証する。実機操作感は別途確認する。

## DBとセキュリティ

DBが現在の2候補・スコア・拾得KPを所有。クライアントから報酬数値を受け付けない。開始ID、現在のステップ番号、左右の選択だけをRPCに送信する。各移動の最低所要時間・期限も検証する。自動操作や改変クライアントの完全な検出を目的とする仕組みではない。

`pyon_runs`は本人のSELECTだけ許可。`pyon_config`は認証済みのSELECTだけ許可。既存のRLS・既存RPCは変更しない。

付与時にprofilesの本人行とrunを同じ順序でロックし、日次集計・ゲーム確定・台帳追加・残高加算を1トランザクションで実行する。ゲームIDの台帳unique indexも二重付与を防ぐ。0付与もrunに記録するが、KP台帳は正の付与だけ記録する。

通信再試行は同じID・同じステップを送る。確定済みの結果はそのまま返す。別タブで新しいゲームを開始した場合、前の未完了ゲームは報酬なしで終了する。タブを閉じたプレイは自動付与しない。日付は付与時の日本時間で決める。日次30KP後もプレイは可能。

### 池・岸背景

`src/game/PyonBackground.tsx` が背景専用レイヤー。素材は実際の格納先
`assets/game/backgrounds/` の水面・固定遠景・左岸A/Bを読み込む。
`BACKGROUND` に岸画像幅（フィールド幅の26%、透過余白込み）、岸44px/ぴょん、
水面18px/ぴょん、時間（既存の `ADVANCE_MS` = 180ms）、遠景縮小率0.87を集約。

水面・左右岸は元画像の1:2比率を保って上下に複数配置する。画面外も余分に用意し、
距離からタイル番号を計算して、画面外へ抜けた分だけ入れ替える。左岸のA/Bはタイル番号から
決定し、同じ番号の右岸は必ず反対の素材（左A→右B、左B→右A）を使う。
同じタイルの画像は途中で変えない。ゲーム用乱数は使わない。
前進フェーズだけCSSのtranslate3dアニメーションを動かし、待機・ジャンプ中は停止する。
背景専用の毎フレームstate更新や待ち時間はない。

岸の連結レイヤー全体に外側の端を固定する弱い遠近変形を適用し、画面上側の岸を内側へ寄せる。
各タイルを個別変形せず接続を維持する。背景はpointer-events:noneで、ハス・カエルより背面。
画像に含まれる動物は判定対象にならない。ゲーム処理・DB処理は変更しない。

`bank_right_a.png` / `bank_right_b.png` は使用しない。右岸は左岸画像を
`pyon.css` の `.pyon-bg-strip--right img` で `scaleX(-1)` により表示時だけ反転する。
右端基準の配置と中央の変形原点で、画像枠の位置を維持する。画像ファイルの加工・複製は行わない。

`scripts/browser/pyon-background.spec.ts` は375/390/430pxで50回の前進・画像境界越え、
A/A・A/B・B/A・B/Bの接続、左右の補完関係、反転、移動量、待機停止、画像と座標の連続性、
固定遠景、DOM数の上限、横はみ出しを検証する。

### オブジェクト表示の詳細

- `pyonMotion.ts` の `project()` で奥ほどハス・レーン間隔を縮小。遠景は状態を持たない仮のハスで、次の危険を先読みできない。
- 背面カエルの素材は `PyonArt.tsx` の `FROG_ASSETS` に待機・直進・左・右のPNGパスを指定して交換する。ハス・穴・KP・天敵は `Lily`、水面は `.pyon-water` が交換箇所。
- 同じレーンなら直進、左→右なら右、右→左なら左ジャンプ。ジャンプ300ms（サーバーの最低時間が長ければそちらを優先）、着地45ms、前進180ms。通信待ち時間は別途発生する。
- 到着まで旧ステージを保持し、着地のRPC確認時にスコアを反映。その後ハスを手前へ移動・拡大し、前進完了時に操作と画面の判断タイマーを再開する。DBの通信猶予・期限判定は既存のまま。
- 入力直後にrefでロックし、ボタンも無効化。再試行は同じRPCのみを送り、ジャンプを再実行しない。危険地点でもジャンプと簡易落下を表示してから結果画面へ進む。
- ブラウザテストは375/390/430/1024pxのレイアウト、再送、時間切れに加え、方向・着地・前進中のロックと判断時間を検証する。実機のタッチ感覚は別途確認する。
